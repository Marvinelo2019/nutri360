# Private branded meal-plan PDF

Status: complete and browser-validated.

## Outcome

An owner can configure the clinic identity used on documents, and a nutrition professional can generate and privately download a polished, two-page PDF from an immutable meal plan.

## Scope

Included:

- Owner-managed clinic name, brand color, phone, and optional PNG/JPEG logo.
- Server-side PDF generation for active or archived plans with patient name, validity, targets, meal structure, guidance, and general instructions.
- A fixed two-page, mobile-readable layout that never silently omits plan content; plans that exceed the safe layout limit receive a clear error and remain unchanged.
- Private Supabase Storage buckets, organization-scoped object policies, stored document metadata, audited generation/download, and authenticated downloads.
- Loading, success, error, missing-branding, and oversized-plan states.

Excluded:

- Public PDF URLs, email or WhatsApp delivery, patient-portal access, electronic signatures, arbitrary document templates, and editing an already generated PDF.
- Individual-food database work, which remains paused pending professional and licensing validation.

## Context

- `organizations` already stores `name`, `brand_color`, `phone_e164`, and `logo_path`.
- Meal plans become immutable after activation; generated documents must use an active or archived snapshot, never an editable draft.
- `docs/PRODUCT.md` and `docs/ROADMAP.md` require a branded PDF that fits two mobile-readable pages.
- `docs/ARCHITECTURE.md` requires private object storage and PDF work isolated from clinical form submissions.

## Security and privacy

- Only active owners can change organization branding.
- Only active owners and nutritionists can generate or download a clinical plan PDF.
- Storage paths begin with the authenticated organization ID and policies re-check active role membership.
- PDFs and logos live in private buckets; no persistent public URL is created.
- Logo uploads accept PNG/JPEG only, enforce a size limit, and use a server-derived object path.
- Audit metadata contains identifiers and object paths only, never patient names or plan content.
- Error logs must not contain meal items, instructions, patient names, or generated bytes.

## Verification

- Database tests prove assistants and other organizations cannot register, read, or download plan documents.
- Unit tests cover color parsing, text wrapping, two-page layout capacity, and Spanish characters.
- A generated synthetic PDF has exactly two pages, extractable expected text, and no clipping, overlap, broken glyphs, or unreadable sections in rendered PNGs.
- Application lint, strict TypeScript, tests, formatting, production build, database tests, and database lint pass.
- The user validates branding, generation, and private download in the browser before the Git checkpoint.
